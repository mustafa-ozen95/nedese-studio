Video

Turns an image into a video.

Video settings

Pick an image and describe how it should move.

The first frame is drawn from this description with the image model, then it is animated with the motion prompt.
Source image required

No image selected

Upload, drag it here or pick from the gallery.

If left empty, a natural, gentle camera motion is used. In a long video each line is one part (≈5 s); with a single line the continuation is written automatically without repeating the action. The video model understands English much better; a Turkish prompt is translated before sending.
Long videos are generated in 5-second parts and joined.
No upper limit; a very long video can take days.
Fine settings
Long video Reduces color and brightness drift between parts; each part's first frame is corrected to match the original image. The end of each part is drawn from the first image with Qwen-Image-Edit and the part is generated between the two frames; a frame with a duplicated character is rejected by the local vision model. Measured (06.10.2026, 60 s): with it off the cat lost its outfit after 12 s (25 of 60 frames), with it on in 4; takes ~50% longer. Not used for single-part videos or 5B. Experimental, not recommended: in the 06.10.2026 test it duplicated the character (2-3 cats in the scene), added a text strip at the top and made the job 18% slower. Before each continuation part, the last frame is corrected with Qwen-Image-Edit to match the character in the first image. Not used when keyframes are on.
Randomness number. Leave empty for a different result each time. The number of a result you like is shown in the job details; enter it here to get the same result again (or a similar one if you tweak the prompt).

Training

Train with your own data: text model (text, code; improve an existing one or start from scratch), image, music and video LoRA. The text model appears in the Settings > Text model list, the LoRA in the Image, Music or Video tab.

Collect training data from the web: a topic, sites or Wikimedia Commons; collected collections are selected as data in the Model training tab.

Model training Data collection
The training environment is not installed (training\.venv). Run setup.bat.
A ready model is downloaded from Hugging Face the first time. If you pick a model you trained here, it is improved with the new data. For another text model, type "org/model".

LoRA for FLUX.2 klein 4B: teaches a style, product or character with 15-30 images. When done it is selected as "LoRA" with FLUX.2 klein in the Image tab; the trigger word calls the LoRA in the prompt. Same-name .txt files become captions (otherwise trigger word + general description). ~20 images at 1024 px take 1-2 hours.

LoRA for ACE-Step 1.5: teaches a style, vocal timbre or instrument sound from a few songs (Turkish songs also improve Turkish pronunciation). When done it is selected as "LoRA" in the Music tab; the trigger word is added to the start of the style. A same-name .txt file becomes the lyrics, .caption.txt the description. Time: 10 three-minute songs take ~2 hours with the default 800 epochs.

LoRA for Wan 2.2 5B: teaches a motion, visual style or character from a few clips or images. Uses the installed model, no download; training runs in ComfyUI. When done, it is selected as "LoRA" in the Video tab under Fine settings > Model: Wan 2.2 5B; the trigger word is added to the prompt. A .txt file with the same name as the clip or image becomes its caption. Time: at 480p with 33 frames ~3.4 s per step; 1000 steps ~1 hour.

For clips without captions (English works best).

A single model that understands image and text together (Qwen3.5): it learns to caption your images in your own style and to answer your questions with your own knowledge. When done, it appears in the Settings > Text model list as "understands images"; /llm/v1 requests can send images (image_url). 4B: 20 examples ~1 min, ~9 GB is downloaded the first time.

Training from scratch needs a lot of data: at least a few MB of text. A small model takes minutes, a large one hours. It has no general language knowledge; it only learns the style and topics of your texts.

Data collection

Collect training data from the web: given a topic, it searches and discovers sites on its own; it collects text, documents (PDF/Office), image/video/audio metadata, SEO meta and translation pairs; the local model extracts the content and tags it with quality, accuracy, category and labels.

Running again with the same name adds new articles; the same article is never taken twice.
With a topic the tool works on its own: it generates search queries (the search services of Settings › Web search first, then Bing, DuckDuckGo, Google News, Wikipedia; MCP servers and skills below), collects the result pages, discovers the feed, sitemap or WordPress API of productive sites, crawls within them and hops from site to site via links on on-topic pages. When media is downloaded it also searches Wikimedia Commons. With target 0 it collects until you stop it; if another job is added meanwhile it yields the queue and resumes where it left off once that job is done. A source list can be given too; both together also work.
One address per line: site, RSS/Atom, OPML, sitemap, WordPress API, page or a PDF/Word/Excel/PowerPoint link. Internal links are classified as article / listing / static / document and followed up to the depth. Sequential requests per site, robots.txt, back-off and rest on 429/503.
Search engines (topic)
Loading…
The search services set in Settings › Web search are asked first, one search at a time; Bing and DuckDuckGo only for the queries no service answered. A service that is not set cannot be picked here.
Beside the web search the local model calls the tools of these servers that search or read (never one that writes, deletes or sends); their text becomes articles and the addresses in them are crawled. Every call is in the job log.
The SKILL.md text of a skill guides the local model where it plans the crawl (search queries, the manager, MCP calls) as instructions for finding and judging sources. Its scripts are not run.

Web search

The assistant's web search (search_web) uses a search service set here before the browser: steadier answers. Without one it searches DuckDuckGo and Bing in a headless browser.

Tried in this order: Brave, Tavily, SearXNG; if none gives results, the browser. Keys stay on this computer (panel-data) and the page shows only their last 4 characters. SearXNG: your own server, e.g. http://127.0.0.1:8888; its settings.yml must allow the json format (search.formats).

Remote model

A text model served elsewhere: Claude, DeepSeek, OpenAI, OpenRouter, Groq, or vLLM, Ollama and LM Studio on another computer. A chat can choose it as its text model in Options.

Fill in for
The base address; the panel sends to it + /chat/completions (Claude: + /messages).
Not set
As the server lists it, e.g. claude-sonnet-5-5, deepseek-flash, gpt-4o-mini, qwen2.5:14b.
Chats on the local model answer with the remote model while an image or video job holds the GPU, instead of waiting for it.
The key stays on this computer (panel-data) and the page shows only its last 4 characters. Images in a chat go only to Claude.
